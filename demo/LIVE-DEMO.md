## 体験の順番

1. **Googleでログインし「体験をはじめる」**を押します。自分専用のお客様と体験領域ができます。同じGoogleアカウントなら途中から再開できます。
2. **通知用LINEを追加**します。画面で本人確認メッセージを作り、その全文を通知用LINEへ送信。返信されたコードを画面へ入力します。「これから2時間、体験通知を受け取る」も押してください。
3. **お客様役のLINEを追加**します。手順2とは別の本人確認メッセージを、このLINEへ送ります。返信コードを画面へ入力すると、LINEの表示名で自分が登録されます。
4. **新しい議事録をLINEで紐付けます。** 画面の見本で「議事録を追加する」を押すか、共通の議事録を取り込みます。通知用LINEに紐付け確認カードが届いたら、原文を確認して**「このお客様に紐づける」**を押してください。こちらが推奨の体験経路です。「今回は紐づけない」も選べます。希望条件・要約は画面に自動反映されます。新しい議事録の明示的な変更を反映し、記載のない条件は根拠付きで引き継ぎます。Web画面の紐付けボタンは予備の経路です。
5. **希望に合う物件を1件足します。** 見本の「渋谷区・5,500万円以内・2LDK・所有権・徒歩10分以内」に対して、画面の初期値「渋谷区・4,800万円・2LDK・徒歩5分」を保存すれば試せます。追加した行はスプレッドシートにも保存され、「スプレッドシートに保存済み」と表示されます。別の生成ボタンを押さずに提案を待ちます。
6. **理由と文案を確認・編集して承認します。** 画面または通知用LINEから操作できます。編集したら必ず最新版を承認します。承認した文面だけが、お客様役のLINEからご自身へ届きます。別の案では「見送り」と理由も試してください。
7. **届いた文面の予約リンクを開きます。** 専用リンクからTimeRexへ進み、空いている日時を選びます。予約がつなぐへ反映され、顧客用LINEへ予約結果が届きます。営業側にも予約のお知らせが届き、予約前の追客は止まります。
8. **予約の取消と、次の変化を試します。** TimeRexの確認メール・予約確認リンクから取り消します。取り消した後、議事録の希望条件や物件を更新すると、次の提案につながります。最後に「体験を終えて、通知を停止する」を押してください。

**TimeRexは実際に予定を確保します。実際の接客・内見を依頼する予約ではありません。体験後は必ず取り消してください。**

予約ページは https://timerex.net/s/gs-estate/59cbab21 です。ただし、LINE本人との対応を引き継ぐため、体験中は**提案文または体験画面にある自分専用の予約リンク**から開いてください。上の共通URLへ直接アクセスした予約は、自分のLINEへ自動で紐付きません。

## その場で試すと違いが分かること

| 試すこと | 見るポイント |
|---|---|
| 議事録を追加し、通知用LINEで紐付け | LINEの選択で解析が始まり、希望条件が画面に自動反映される |
| スプレッドシートへ新しい物件行を直接追加 | 手動更新・生成ボタンを押さずに検知・照合・提案される |
| 予算・エリアを議事録で変更 | 条件が更新され、古い条件の未送信提案が止まる |
| 希望に合う物件を追加 | 顧客との一致理由と文案が自動でできる |
| 希望に合わない物件、売約済み物件を追加 | 無理な提案を作らない |
| 同じ内容のまま待つ | 同じ更新で提案・通知が増え続けない |
| 文案を短く編集して承認 | 編集差分と承認した版が履歴に残る |
| 事実訂正・顧客固有の事情を記録 | 文体の学習と分け、対象の情報・顧客に限定して使う |
| 予約・取消 | 日程と顧客の状態が変わり、不要な追客が止まる |

学習は、承認済みの表現や判断を次の生成に渡すfew-shot方式です。モデルの再訓練ではありません。1回の編集で品質が改善すると保証するものではなく、履歴と次回の文章を比べて評価してください。

## 共通素材と自分のデータ

- [商品マスタ（Googleスプレッドシート）](https://docs.google.com/spreadsheets/d/180qti_r78KjqPLVi_-fnZX-fRQSZ_qoQph8Usp6gpbg/edit)
- [議事録の読取フォルダ](https://drive.google.com/drive/folders/1ATiHVcSwZu-jgb6oVVyjTZVbH7UiqQ7h)

共通の架空素材は体験画面から取り込めます。Googleファイルの編集権限がなくても、画面内で自分用の議事録・物件を追加して試せます。共通議事録からの取込は、自分専用のコピーです。そのコピーを更新すると自動解析します。共通の原本を変更した場合は、原本の自動同期後に改めて取り込んでください。

通知を有効にした体験中は、共通の商品マスタ・原本フォルダを約30〜60秒間隔で確認します。体験画面が表示中なら共通の処理を共有して約30秒間隔、閉じていても1分ごとの定期実行が補完します。体験通知が無効の通常時は原則5分間隔です。AI解析中などは追加で時間がかかります。体験画面は10秒ごとに状態を確認するため、ブラウザーの再読込は不要です。

新しい共通原本をDriveに追加すると、通知を有効にした各体験者へカードが届き、それぞれの顧客へ個別に紐付けできます。フォーム由来の物件行は本人の体験用、シートへ直接作った別IDの行は共通物件です。フォーム由来の物件IDは変更しないでください。

シートへ直接追加する際は18列を埋め、物件IDを重複させず、価格・徒歩を数値、在庫を「販売中」、区分を「架空」、データ版を1以上にします。公開・在庫確認日時は現在以前、有効期限は未来。日時は `2026-10-05T10:00:00+09:00` の形式です。在庫確認が24時間より古い行や、数式を含む台帳は提案に使いません。

自動生成した文案の数値・引用チェックに失敗した場合は、理由をAIへ返して1回だけ自動修正・再検証します。「AIが作成・再検証中」は操作せず待ってください。修正もAI利用枠を1回消費します（初回と合わせて最大2回）。元情報の矛盾や条件変更、再検証でも解消しない問題は「再確認」に止め、未検証の文案を通知・自動送信しません。

## 途中で困ったら

| 状況 | 対応 |
|---|---|
| 台帳の保存結果が確認中 | 同じ物件を新しく追加し直さず結果を待つ。物件IDで照合して重複追加を防止します |
| 台帳保存のエラー・競合 | 編集権限または台帳側の変更を確認。確定した失敗は「保存を再試行する」から再開できます |
| LINEの確認コードが合わない | 通知用と顧客用を取り違えていないか確認。期限切れならメッセージを再発行 |
| 本人確認が「保存途中」と表示される | 確認メッセージを再発行し、同じLINEで返信コードを受け取って再入力。途中の記録を引き継いで完了できます |
| 以前使ったLINEが連携済み | 最初に使ったGoogleアカウントでログイン。別人の登録へ付け替えることはできません |
| 議事録の解析が止まった | 表示された理由を読み、希望エリア・予算・必須条件を補足して解析をやり直す |
| 古い議事録を追加しても希望条件が変わらない | 面談日時が新しい議事録を優先します。古いものは履歴として保存され、画面にその旨が表示されます |
| AI文案が「再確認」になった | 自動修正でも解消しない問題や元情報の不足・矛盾です。理由は通常表示に残ります。「最新の根拠で文案を再生成する（1回分）」または文面の編集で再確認。参考テンプレートは生成完了と区別されます |
| 条件変更の確認を求められた | 未定・相反する希望は自動で上書きしません。原文を確認し、確定した希望を議事録へ追記して更新します |
| 提案が来ない | LINE本人確認、通知の2時間枠、希望と物件の一致、販売中か、解析が完了したかを確認 |
| 「最新版を確認」などで送信が止まる | 最新カードを開く。議事録・在庫・新着返信が変わった場合は、古い案を送らず新しい案を待つ |
| 予約はできたがLINEが来ない | 自分専用リンクから予約したか、顧客用LINEをブロックしていないかを確認。予約画面の通知状態も確認 |
| 送信結果が「確認中」 | 重複を防ぐため、自動で再送しません。LINEの受信と画面状態を確認 |
| 利用枠が満員・上限 | 約10人向けの提出環境です。枠の追加は運営へ連絡。AIは1人1日12回、顧客用送信は予約通知込みで1人1日8回 |

AIへの入力は架空の体験データにしてください。作成した議事録・文案・操作履歴は体験環境に保存されます。実際のお客様の機微な情報を使う体験ではありません。

## 今回のライブ体験の範囲

議事録の要約・条件抽出、物件との照合、文案・通知、編集・承認・自己宛LINE送信、TimeRexの予約・取消を通す構成です。リサーチ、Googleカレンダー、再連絡期限の検知も別途実装していますが、無人デモの主経路ではありません。マイソクPDF・ExcelのAI抽出は今回の実機検証対象外です。
