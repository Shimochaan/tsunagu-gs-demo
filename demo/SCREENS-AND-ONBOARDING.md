# 全画面の役割と、企業への導入フロー

見学URL：https://tsunagu-gs-showcase.shimoryo.workers.dev/login

ログイン：**demo@example.com**。パスワード・確認メールは不要。実製品の画面とAPIを、独立した架空データの環境で動かしています。フォーム・タブ・詳細を見られますが、保存・送信・外部接続は停止しています。画面の比較のため複数の役割をまとめたアカウントで、本運用の権限構成とは異なります。

メインの実機体験は[既存ガイド](LIVE-DEMO.md)。Googleでログインし、自分のLINEで議事録・物件・編集・承認・送信・予約を試します。

## 受注から開通まで

### 1. 運営が受注登録

担当：運営。企業・契約・導入方法（代行／レクチャー／顧客設定）を登録し、初期管理者を招待。

### 2. 招待からログイン

担当：企業管理者。招待されたメールのGoogleログイン、またはメール確認コードで参加。所属と役割を確認。

### 3. 公式LINEと基盤を準備

担当：企業管理者＋運営。担当者別・店舗別・企業共通から運用単位を選択。顧客用LINEの接続・Webhook確認、HarnessとDBを準備。既存Lステップ等がある場合は受信経路・併用可否を個別に確認。

### 4. 情報元と営業を接続

担当：企業管理者＋営業。商品マスタ、Drive議事録、カレンダー、TimeRex等の利用する情報元を接続。営業を招待し、文体・担当顧客を設定。営業本人が通知用LINEの本人確認を行う。

### 5. 確認して開通

担当：企業管理者。顧客対応付け・希望条件・プレビューを確認。自己宛送受信・予約反映をテストして開通。顧客ごとの既存会話の取り込みは接続先の機能・取得可能範囲による。

### 6. 毎日の営業

担当：営業。情報の更新を自動検知 → 顧客条件と照合 → 根拠付き文案が届く → 編集・承認・見送り → 顧客送信・予約 → 議事録へ。判断を次回へ反映する。


## DBの共有と権限

顧客の基本情報は企業ごとの共通DBに保存します。会話（Harness）・商品マスタ・議事録・文体・提案（TSUNAGU）は公式LINE（OA）単位のDBです。同じOAを扱う営業は役割・担当・チーム共有設定に応じて使えます。複数OAの商品情報を自動で企業全体へ集約する機能ではありません。運営の支援は目的・範囲・期限と企業側承認を持つ手続きを使います。

既存Lステップ等がある企業では、Webhookの受信先、共存方法、取得できる会話や友だちの範囲を確認してから接続します。未構築ならHarnessから準備します。管理画面で企業を追加しただけで、外部サービスの認可や開通テストまで完了するわけではありません。

## この見学の範囲

- 架空の顧客3人、議事録2件、物件1件、文案1件、予約1件を用意しています。実在の商談・契約ではありません。料金・原価も架空例です。
- 見学ログインの有効期間は2時間。再度同じメールで入れます。共有の見本データは変更できません。
- 見学中の保存・承認・送信・新規接続は説明メッセージを表示して停止します。AI費用やLINE送信は発生しません。
- 本運用では招待・役割による制御、運営のMFA、外部接続の認可が必要です。見学用ログインは実機デモ・本運用の認証には使えません。
- リサーチ・Googleカレンダー・マイソク取り込みの設定画面は閲覧できます。請求書画面は未発行の表示です。すべての外部機能の実機検証完了を示すものではありません。
- AI枠は実機デモの一般体験者12回/日、既存の企業管理者100回/日、全体300回/日。既に使った回数を保持したまま上限を増やしています。利用枠は日本時間の日付で集計します。

## 開発者向け：見学環境の再構築

`wrangler.showcase.example.jsonc` を元に、独立したWorkerと新しい4つのD1を用意します。`scripts/seed-showcase.ts /tmp/任意の新規ディレクトリ` が架空データのみのSQLを生成します。SQLは新しい見学DBだけに適用してください。運用中のDBへ見学用ユーザーを追加しないでください。

`AUTH_SECRET` と `CREDENTIAL_KEY` は専用のランダム値をCloudflare Secretへ保存します。Google・LINE・AI・TimeRexの資格情報は不要です。通常環境には見学用のログインを登録しません。見学の保存停止は画面表示だけでなく、Workerのすべての更新リクエストに適用します。
