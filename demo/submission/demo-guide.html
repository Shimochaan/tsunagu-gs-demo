実際の企業へ導入する流れ

1. 運営が受注登録（運営）
企業・契約・導入方法（代行／レクチャー／顧客設定）を登録し、初期管理者を招待。

2. 招待からログイン（企業管理者）
招待されたメールのGoogleログイン、またはメール確認コードで参加。所属と役割を確認。

3. 公式LINEと基盤を準備（企業管理者＋運営）
担当者別・店舗別・企業共通から運用単位を選択。顧客用LINEの接続・Webhook確認、HarnessとDBを準備。既存Lステップ等がある場合は受信経路・併用可否を個別に確認。

4. 情報元と営業を接続（企業管理者＋営業）
商品マスタ、Drive議事録、カレンダー、TimeRex等の利用する情報元を接続。営業を招待し、文体・担当顧客を設定。営業本人が通知用LINEの本人確認を行う。

5. 確認して開通（企業管理者）
顧客対応付け・希望条件・プレビューを確認。自己宛送受信・予約反映をテストして開通。顧客ごとの既存会話の取り込みは接続先の機能・取得可能範囲による。

6. 毎日の営業（営業）
情報の更新を自動検知 → 顧客条件と照合 → 根拠付き文案が届く → 編集・承認・見送り → 顧客送信・予約 → 議事録へ。判断を次回へ反映する。

顧客DBは企業ごとに共有し、担当・役割でアクセスを制御。商品マスタ・議事録・提案は公式LINE（OA）単位で共有します。複数OAの商品情報を企業全体へ自動集約する機能ではありません。

自分のLINEに届くまで

Googleでログイン

体験画面を開き「体験をはじめる」。営業役とお客様役を、あなた自身が兼ねます。

2つのLINEを追加・本人確認

それぞれの画面で作る確認メッセージを、対応するLINEへ送ります。返信コードを同じ画面へ入力し、2時間の体験通知を有効にします。

新しい議事録をLINEで紐付ける

共通素材を取り込むか、見本入りの面談メモを追加。通知用LINEに届くカードの「このお客様に紐づける」を押すと解析が始まります。

希望に合う物件を足す

見本なら「渋谷区・4,800万円・2LDK・徒歩5分」。スプレッドシートにも保存され、条件を照合し、理由付きの文案ができ、通知用LINEへ届きます。

編集・承認して、自分のLINEで受信

文面と根拠を確認。修正したら最新版を承認します。見送り理由や修正の種類も残せます。

文中のリンクから予約・通知を受信

TimeRexで日時を選びます。予約結果が自分の顧客用LINEへ届き、営業側にも反映。体験後は予約確認リンクから取り消してください。

見てほしいのは「文章生成」の先

情報の更新 → 顧客との一致 → 根拠付き文案 → LINEへ提案
→ 営業が編集・承認・見送り → 判断を記録 → 次のご連絡へ

希望を変える、合わない物件を入れる、売約済みにする。そんな変化も試してください。古い情報では送らず、同じ更新を何度も通知しないことも大切な体験です。

学習は承認済み事例を次回へ渡すfew-shot方式。文体、事実訂正、この顧客だけの事情を分けて使います。

予約は自分専用のリンクから

体験画面・届いた提案文からTimeRexへ進んでください。共通URLを直接開くとLINE本人との紐付けを引き継げません。

TimeRexは実際の日時を確保します。体験後は必ず取り消してください。実際の接客・内見を依頼する予約ではありません。

予約先：G’s不動産・TimeRex

止まったときの確認

LINEのコードが合わない・返ってこない

通知用と顧客用の送り先・確認コードは別です。画面からメッセージを再発行し、全文を送り直してください。公式LINEをブロックしていないかも確認します。

提案が来ない

本人確認、2時間の通知枠、議事録の解析完了、物件と希望の一致、販売中かを確認してください。画面は10秒ごとに自動更新。通知が有効な体験中は約30〜60秒間隔で共通Google素材を確認し、その後に解析が続きます。

予約・送信の結果が確認中

結果不明時は重複を防ぐため自動再送しません。実LINEの受信、予約ページの最新状態を確認してください。上限はAIが体験者1人1日12回（既存の検証管理者は100回、全体300回）、顧客向け送信が予約通知込みで1日8回です。

約10人向けの提出用環境。共通素材は架空データです。自分用メモ・物件をその場で追加できます。実際のお客様の機微な情報を入力しないでください。
